# WL Parser

Бот следит за сетью **Robinhood Chain** и присылает в Telegram сообщение, когда
в сети появляется новая NFT-коллекция или начинается минт — обычно до того, как
про проект напишут в твиттере.

Работают два источника: **блокчейн** (факт минта) и **Twitter** (анонс WL
за часы до минта). Discord — следующий этап. Умеет и сам постить находки
в X (см. «Автопост в X» ниже).

---

## Запуск

### Windows

Двойной клик по **`start.bat`** — всё.

При первом запуске он сам поставит зависимости и проведёт по настройке,
дальше будет просто запускать бота. Остановить — закрыть окно или Ctrl+C.

Нужен Python 3.11 или новее. Если его нет, батник скажет об этом и даст ссылку;
при установке обязательно поставь галочку **«Add python.exe to PATH»**.

### Mac (в контейнере)

Двойной клик по **`mac-start.command`**.

Нужен [Docker Desktop](https://www.docker.com/products/docker-desktop/) —
версия для Apple Silicon. Скрипт сам скажет, если его нет или он не запущен.

При первом запуске он соберёт контейнер (пара минут) и проведёт по настройке.
Дальше бот работает в фоне и переживает перезагрузку ноутбука: закрывать окно
с логами можно спокойно, он от этого не остановится.

| Файл | Что делает |
|---|---|
| `mac-start.command` | Запустить (и настроить при первом запуске) |
| `mac-stop.command` | Остановить |
| `mac-twitter.command` | Подключить аккаунт X |

Настройки и база находок лежат в папках `config/` и `data/` рядом со скриптами —
пересборка контейнера их не трогает.

Внутри контейнера видны только эти две папки, поэтому секреты там лежат в
`config/.env`, а не в корне проекта как на Windows. Скрипт запуска переносит
файл сам, если он ещё не перенесён.

> Если файл не запускается двойным кликом, macOS мог снять права на исполнение
> при копировании. Открой Терминал в папке проекта и выполни:
> `chmod +x *.command`

> **Только одна машина одновременно.** Telegram разрешает получать сообщения
> лишь одному экземпляру бота: если запустить его и на Windows, и на Mac с тем
> же токеном, оба начнут отваливаться с ошибкой 409, и подписчики перестанут
> получать ответы на команды. Останови бота на первом ноуте, прежде чем
> запускать на втором. Нужны оба сразу — заведи второй токен у @BotFather.

При переносе скопируй на Mac всю папку проекта вместе с `config/` и `data/`:
в них лежат настройки, токен и уже найденные проекты. Без `data/` бот начнёт
с чистого листа и заново пришлёт то, о чём уже сообщал.

### Командная строка (любая система)

```bash
python -m pip install -e .
python -m wlparser setup
python -m wlparser run
```

На Mac это тоже рабочий путь, если ставить Docker не хочется: нужен только
Python 3.11+. Минус — бот живёт, пока открыт терминал.

### Автообновление на Маке через GitHub

Если код правится на Windows (или где угодно ещё), Мак может сам подтягивать
изменения и пересобирать контейнер — без ручного переноса zip-архивов.

Разово нужно:

1. Создать **приватный** репозиторий на GitHub (Settings → New repository,
   без README) и дать мне его адрес.
2. На Маке — **приватный** доступ на чтение. Проще всего: GitHub → Settings
   → Developer settings → Fine-grained tokens → New token, доступ только
   к этому репозиторию, права **Contents: Read-only**. Токен вставляется
   прямо в адрес репозитория при клонировании:
   `git clone https://<токен>@github.com/<аккаунт>/<репозиторий>.git`
3. В склонированную (не распакованную из zip!) папку скопировать `config/`
   и `data/` из прежней рабочей копии — секреты и история в git не попадают.
4. Запустить **`mac-autopull-install.command`** — раз в 5 минут Мак сам
   сверяется с GitHub и, если код изменился, подтягивает его и выполняет
   `docker compose up -d --build`. Кнопка «🔄 Обновить с GitHub» прямо в
   самом боте (см. `/menu`) работает через тот же цикл: launchd следит за
   файлом-флагом (`WatchPaths`) и запускает проверку сразу же, не дожидаясь
   планового пятиминутного цикла.

| Файл | Что делает |
|---|---|
| `mac-autopull-install.command` | Включить автообновление (плановое + по кнопке) |
| `mac-autopull-uninstall.command` | Выключить |

Лог проверок — `autopull.log` в папке проекта. Работает только если папка
получена через `git clone`, а не распакована из zip — в ней должен быть
git-репозиторий, которому есть, откуда тянуть.

### Свой сервер

Тот же контейнер разворачивается на VPS без изменений:

```bash
docker compose run --rm bot setup
docker compose up -d
```

`restart: unless-stopped` поднимет бота после перезагрузки сервера.

## Настройка

`python -m wlparser setup` задаёт два вопроса.

### Шаг 1. Адрес RPC

Это адрес, по которому бот читает блокчейн. Найти можно на
[chainlist.org](https://chainlist.org) или в документации сети — ищи
Robinhood Chain и строку вида `https://...`.

Мастер сразу проверит адрес и скажет, годится ли он. Проверяются три вещи:
отвечает ли сервер, видит ли он текущий блок, и умеет ли отдавать логи событий.
Последнее критично — без логов бот не увидит минты. Если адрес не подошёл,
мастер просто спросит следующий.

Заодно можно указать адрес эксплорера — тогда в каждом алерте будет прямая
ссылка на контракт.

### Шаг 2. Telegram

1. Открой в Telegram бота **@BotFather**, отправь `/newbot`, придумай имя.
   В ответ придёт токен вида `1234567:AAF...` — вставь его.
2. Напиши своему новому боту любое сообщение (иначе он не сможет тебе писать).
3. Открой **@userinfobot** — он покажет твой числовой id. Вставь его.

Всё. Настройки лягут в `config/config.yaml`, токены — в `.env`.
Оба файла не попадают в git.

## Что присылает бот

| Значок | Событие | Когда приходит |
|---|---|---|
| 🔥 | Всплеск минта | Мгновенно — массово разбирают прямо сейчас, ждать нельзя. |
| ⏳ | Почти распродано | Мгновенно — раздача может закрыться за минуты. |
| 🆕 | Новый контракт | В дайджесте (ниже). |
| 🚀 | Начался минт | В дайджесте. |
| 🎟 | Анонс WL | В дайджесте. |

Мгновенно будят только по-настоящему срочные события — всплеск минта и
приближение к распродаже. Всё остальное (новые контракты, старт минта,
анонсы в твиттере) копится в базе и приходит **дайджестом раз в два
часа** (по умолчанию каждый чётный час по времени, в котором работает
Мак/сервер — настраивается в `config.yaml` секцией `digest`): проекты —
с оценкой интересности, анонсы в твиттере — с короткой оценкой от
локальной модели ("похоже на шаблонный пост" / "конкретика, стоит
посмотреть" и т.п., при выключенном `llm` просто без неё). Так бот не
дёргает уведомлениями на каждую находку, но ничего не теряется — всё
отслеживается и попадает в дайджест независимо от того, ушёл ли по нему
мгновенный алерт.

Мгновенные алерты по одной коллекции складываются **в одну ветку
сообщений** и обновляются на месте (см. следующий раздел) — ссылки на
контракт, OpenSea, твиттер, дискорд и сайт бот находит сам через OpenSea,
настраивать ничего не нужно.

### Живая карточка вместо новых сообщений

Раз найденную коллекцию бот берёт под слежение — причём **сразу же**, не
дожидаясь планового опроса, и для **каждого** найденного контракта, а не
только для тех, что попали в мгновенный алерт: цена, прогресс минта и
оценка интересности собираются в фоне всегда, и именно из этих данных
строится дайджест (см. выше).

Живой карточкой — сообщением, которое правится на месте вместо новых —
становится только то, что реально прислалось мгновенным алертом (🔥/⏳).
Если у проекта такого алерта не было, слежение всё равно идёт, но
отдельного обновляемого сообщения для него нет — актуальную информацию
показывает дайджест и `/find <название>`.

Там, где карточка есть, бот перечитывает состояние контракта в сети
каждые пять минут (чаще — ближе к распродаже) и правит то же сообщение,
а не присылает новое. Прогресс минта и цена читаются напрямую из
блокчейна и работают без единого внешнего ключа. Если задан ключ OpenSea
(см. ниже), в карточке появляются ещё флор-цена на вторичке и число
держателей.

Слежение останавливается само: коллекция распродана, цифры не меняются
двенадцать проверок подряд, или прошёл месяц — вечно опрашивать
заброшенный контракт незачем.

### Больше статистики с OpenSea

В живой карточке появились: общий объём торгов и число продаж коллекции,
средняя цена продажи. Всё это приходит тем же самым запросом, которым бот
и так получает флор и число держателей, — без единого лишнего обращения
к API.

Требует того же ключа OpenSea, что и флор с держателями (см. ниже) —
без ключа этих строк просто не будет в сообщении.

**Важно про валюту.** Флор на OpenSea не всегда в ETH — у части коллекций
он торгуется в стейблкоине вроде USDG, и число тогда означает совсем другую
сумму. Бот показывает ровно ту валюту, что вернул OpenSea (например
«флор: 0.1 USDG»), а не подписывает всё подряд как ETH. По той же причине
эвристика `/top` не сравнивает флор с ценой минта, если флор не в ETH —
делить разные валюты друг на друга бессмысленно.

### Найти проект по названию — /find

Пишешь в бота `/find cash bears` (или просто `/find` и часть названия) —
и получаешь полную карточку по проекту: прогресс минта, цену в ETH и
долларах, флор, объём торгов, а также **последнюю и максимальную цену
продажи среди последних ~50 сделок** на вторичке.

Важная оговорка про «максимальную»: это не исторический рекорд коллекции,
а максимум среди недавних продаж. Пролистать весь архив сделок ради
одного числа было бы слишком дорого по запросам и слишком медленно —
это осознанный компромисс.

Поиск идёт только среди того, что бот уже сам нашёл (в сети или в
твиттере) — не по всему OpenSea. Показываются первые 3 совпадения по
названию или тикеру. То же самое доступно из терминала:

```bash
python -m wlparser find "cash bears"
```

### Что выглядит интереснее — /top

Каждая проверка обновляет эвристическую оценку 0–100: сколько уже
разобрано, как флор соотносится с ценой минта, как быстро растёт число
держателей. Команда `/top` (и `python -m wlparser top`) показывает
отслеживаемые проекты по этой оценке с коротким объяснением.

Это **не финансовый совет и не модель** — правила видны прямо в
[`tracking/scoring.py`](src/wlparser/tracking/scoring.py). Настоящую модель
имеет смысл обучать, когда снимков накопится на несколько недель по
десяткам проектов — таблица `snapshots` как раз и есть та история цены,
из которой она потом будет обучена.

### Цена минта в долларах

Рядом с ценой в ETH бот показывает примерную сумму в долларах — по курсу
CoinGecko (без ключа) плюс оценка комиссии сети (текущая цена газа × условный
расход на транзакцию минта). Работает сразу, без единой настройки.

Это оценка, а не точная сумма: у разных контрактов расход газа на минт
отличается в разы, курс ETH/USD обновляется не мгновенно. Настроить:

```yaml
pricing:
  enabled: true
  gas_per_mint: 150000   # условный расход газа, если хочешь точнее под свою сеть
  include_gas: true      # false — показывать только цену минта без газа
```

### Локальная модель (Ollama)

Если на Маке стоит Ollama (как в проекте Lalascaner: `brew install ollama`,
`brew services start ollama`, `ollama pull llama3.1`), бот подключается к ней
сам — настроек не нужно. Она работает в двух местах:

- пишет тексты для постов в X: факт из алерта переписывается живее, а
  ссылку и хэштеги добавляет код, а не модель. Если модель молчит или
  выдала что-то подозрительное (ссылку, цифру, которой не было в факте),
  остаётся обычный шаблонный текст;
- решает, не спам ли алерт, — последняя проверка перед отправкой, поверх
  обычных фильтров (`mint`, `noise`). Пропускает всё, что не смогла явно
  опознать как мусор: пропустить лишнее не так плохо, как погасить
  настоящую находку.

В обоих случаях недоступная или ошибившаяся модель ничего не ломает — бот
просто работает так, как будто её нет. Жива ли она — видно в боте:
`/menu` → Статус.

Ollama стоит на самом Маке, не в Docker (контейнеры не видят GPU), а из
контейнера её видно по `host.docker.internal:11434` (см. `extra_hosts`
в `docker-compose.yml`).

Выбрать конкретную модель можно одной командой, не редактируя config.yaml —
двойной клик по `mac-llm-model.command` (спросит имя) или из терминала:

```bash
./mac-llm-model.command qwen2.5:3b
```

Либо вручную в конфиге:

```yaml
llm:
  enabled: true
  model: ""          # пусто — первая из скачанных; или, например, qwen2.5:14b
  filter_alerts: true   # false — не отсеивать алерты, только тексты постов
```

### Общая база на любом устройстве (Turso)

По умолчанию у каждой установки бота своя локальная база — то, что нашлось
на Маке, не видно с Windows, и наоборот. Одновременно бот всё равно может
работать только на одном устройстве (так требует Telegram), но историю
находок и цен можно сделать общей, чтобы она не начиналась с нуля при
переезде между машинами.

Для этого нужен бесплатный аккаунт [Turso](https://turso.tech):

1. Зарегистрируйся, установи их CLI, создай базу: `turso db create wlparser`
2. Адрес: `turso db show wlparser` → строка вида
   `libsql://wlparser-имя.turso.io`
3. Токен: `turso db tokens create wlparser`

Проверить, что всё работает, до того как вписывать в конфиг:

```bash
python -m wlparser db-probe libsql://wlparser-имя.turso.io
```

Дальше в `config/config.yaml`:

```yaml
db_url: "libsql://wlparser-имя.turso.io"
```

И в `.env` (или `config/.env` на Маке):

```
DB_AUTH_TOKEN=токен_из_шага_3
```

Пустой `db_url` (по умолчанию) — работа на локальном файле, как раньше.
Если бесплатный лимит Turso закончился и платить не хочется — вернуться
на локальный файл одной командой, не редактируя config.yaml:
`mac-db-use-local.command`. Пробует сначала скопировать историю из Turso
в локальный файл; если Turso недоступна даже для чтения — переключается
на пустую локальную базу, не застревая на этом шаге.

### Соцсети проектов и ключ OpenSea

Ссылки на контракт в эксплорере и на коллекцию в OpenSea строятся из адреса
контракта локально и работают всегда.

А вот твиттер, дискорд и сайт проекта берутся из API OpenSea, и с сентября
2026 года он требует ключ. Ключ бесплатный:
[opensea.io/account/developer](https://opensea.io/account/developer) → создать
ключ → вписать в `config/config.yaml`:

```yaml
links:
  opensea_api_key: "твой ключ"
```

Без ключа бот работает как обычно, просто в уведомлениях не будет строки
с соцсетями проекта.

### Напоминания

Минт начнётся не сейчас, а через час — под каждым сообщением есть кнопка
**⏰ Напомнить**. Нажимаешь, выбираешь через сколько (от 15 минут до суток),
и напоминание приходит **за 10 минут до события**, целиком повторяя исходный
алерт со всеми ссылками. Искать оригинал в переписке не нужно.

Следом можно нажать **📝 Добавить заметку** и написать что угодно — «проверить
флор», «нужен второй кошелёк». Заметка придёт вместе с напоминанием.

На самом напоминании есть кнопка **🔁 Ещё раз за минуту до**: если до старта
ещё есть дела, бот продублирует сообщение прямо перед событием.

Напоминания лежат в базе и переживают перезапуск бота: поставленное на завтра
сработает завтра, даже если ноутбук перезагружался. У каждого подписчика свои.

Время опережения меняется в `config/config.yaml`:

```yaml
alerts:
  reminder_lead_minutes: 10
```

### Как бот отличает раздачу от мусора

Первый минт коллекции не значит ничего: точно так же выглядит тест
разработчика или случайная транзакция. Поэтому алерт приходит не на первый
минт, а когда коллекцию сминтили **минимум 10 разных кошельков за два часа**.
Число мелких уведомлений это убирает почти полностью.

По той же причине всплеск считается по кошелькам, а не по штукам: один бот,
скупивший 40 токенов в одном блоке, — это не ажиотаж, а один бот.

Отдельно отсеиваются служебные NFT — позиции ликвидности Uniswap, домены,
стейкинг-бейджи. Формально это тоже NFT, и минтятся они непрерывно, но
раздачами не являются. Список слов для отсева — в `filters.py`, дополнить
можно через `mint.ignore_name_patterns` в конфиге.

## Команды

| Команда | Что делает |
|---|---|
| `python -m wlparser setup` | Настройка. Можно запускать повторно — ручные правки порогов сохранятся. |
| `python -m wlparser run` | Запуск слежения. Остановить — Ctrl+C. |
| `python -m wlparser recent` | Последние находки, включая те, что не прошли порог алерта. |
| `python -m wlparser chain-probe <адрес>` | Проверить RPC-адрес отдельно. |
| `python -m wlparser twitter-add` | Подключить аккаунт X для чтения ленты. |
| `python -m wlparser twitter-test` | Проверить, что чтение X работает. |
| `python -m wlparser subscribers` | Кто подписан на бота. |

Бот запоминает, до какого блока дошёл. После перезапуска он продолжит с того же
места, а не с текущего момента, — пропущенное за время простоя догонит.

---

## Бот открыт для всех

Любой, кто напишет боту, автоматически подписывается и начинает получать
уведомления — команда для этого не нужна, хватит любого сообщения.

Тебе как владельцу приходит отдельное сообщение о **каждом новом человеке**:
имя, юзернейм, его chat id и сколько всего стало подписчиков. Повторно
пришедший (отписался и вернулся) второй раз не считается.

Команды, которые видят подписчики:

| Команда | Что делает |
|---|---|
| `/start` | Подписаться |
| `/recent` | Последние находки |
| `/help` | Что означают значки в сообщениях |
| `/stop` | Отписаться |

Посмотреть список подписчиков: `python -m wlparser subscribers`.
Тот, кто заблокирует бота, отключается от рассылки автоматически.

Ветка обсуждения проекта своя в каждом чате, так что у тебя и у подписчиков
сообщения группируются одинаково и независимо друг от друга.

### Фора для себя

Бот публичный, значит подписчики получают находки одновременно с тобой.
Если это не то, чего ты хочешь, в `config/config.yaml` есть:

```yaml
alerts:
  owner_head_start_s: 30
```

Тебе сообщение уйдёт сразу, остальным — через полминуты. По умолчанию 0,
то есть всем одновременно.

## Twitter

Блокчейн говорит о том, что уже случилось. Твиттер — о том, что только
собирается: раздачу WL анонсируют за часы до первого минта. Поэтому источник
и нужен, хотя шума в нём заметно больше.

Двойной клик по **`twitter-setup.bat`** — или в командной строке:

```bash
python -m wlparser twitter-add
```

Команда попросит два значения из cookies браузера, где ты залогинен в X:
`F12` → вкладка **Application** → **Cookies** → `https://x.com` → строки
`auth_token` и `ct0`. Скопируй их значения.

> Заведи под это **отдельный аккаунт**. Чтение через cookies нарушает правила
> X, и аккаунт могут заблокировать. Сам бот ничего не лайкает и не
> подписывается, интервалы неровные и со случайным разбросом, — но если
> включишь автопост (см. ниже), он будет публиковать и цитировать чужие
> твиты с этого же аккаунта, так что риск не нулевой.

Батник сразу же и проверит, что чтение работает. Потом в `config/config.yaml` поставить `twitter.enabled: true` и перезапустить.

Бот ищет по запросам из `twitter.queries` (синтаксис обычного поиска X, можно
править под себя) и отдельно читает ленты аккаунтов из `twitter.watchlist`.
Watchlist пока пустой — его наполнит этап 4, когда бот начнёт сам замечать,
кто пишет о проектах раньше остальных.

Из каждого твита вытаскиваются адреса контрактов и ссылки на коллекции —
именно они связывают слух из твиттера с фактом в блокчейне.

## Автопост в X

Публикует находки от своего имени тем же аккаунтом, что настроен на чтение
выше (`twitter.post_as`) — **полностью сам, без подтверждения**: владелец
явно попросил не дёргать его в Telegram на каждую находку.

```bash
./mac-poster-enable.command
```

### Собственные посты

Только всплеск минта и приближение к распродаже (не сам факт старта
минта — тот слишком частый случай, десятки в час в активные периоды) и
только собственные он-чейн факты — никогда чужой текст из твиттера как
свой пост, это не ретвит и не пересказ чужого поста.

Счётного лимита в сутки нет (`poster.max_posts_per_day: null` по
умолчанию) — вместо числа отбор идёт по качеству: перед публикацией
локальная модель отдельно решает, заметна ли конкретно эта находка
(сильный всплеск, крупная/быстрая распродажа), а не рядовой случай.
Любая неопределённость — модель недоступна, не ответила вовремя, ответ
не разобрать — трактуется как "не публикуем": пропустить находку дешевле,
чем выпустить посредственный пост, раз верхней границы по числу больше
нет.

Текст пишет та же локальная модель (см. «Локальная модель» ниже) в одном
из нескольких голосов — не всегда одна и та же конструкция фразы, — а
если она недоступна или её ответ не прошёл проверку (выдуманная цифра,
ссылка, хэштег от себя), уходит шаблонный текст с фактом как есть. Ссылку
на OpenSea и хэштеги в обоих случаях добавляет код, не модель.

### Цитирование чужих твитов

Помимо собственных постов, бот может процитировать чужой твит с анонсом
WL (не любое упоминание темы — только явные анонсы) своим коротким
комментарием, чтобы расширять аудиторию, а не только отчитываться о
находках. Комментарий никогда не подтверждает чужие заявления как факт —
это чужой пост, не проверенный он-чейн сигнал, — и, как и с постами,
локальная модель сперва решает, стоит ли вообще на это реагировать
(обычный шаблонный анонс — не стоит). Без локальной модели цитирование не
работает вовсе: написать честный комментарий без неё нечем, и шаблонного
запасного текста для этого, в отличие от собственных постов, нет.

Для цитирований — отдельный, более осторожный лимит в сутки,
`poster.max_quotes_per_day` (по умолчанию 5): это не собственный факт, а
реакция на чужой пост, и репутационно обходиться с этим стоит
аккуратнее, даже когда у обычных постов верхней границы нет.

### Проверка

Проверить, что публикация реально работает, можно без ожидания настоящей
находки — `/testpost` в боте (только владельцу) пришлёт тестовый черновик
с кнопками подтверждения: это единственное место, где подтверждение
всё ещё есть, потому что это осознанная ручная проверка, а не находка.

## Если что-то идёт не так

**Бот молчит.** Скорее всего в сети просто ничего не происходит — проверь
`python -m wlparser recent`. Если там пусто, а в логах видно движение по блокам,
значит новых коллекций пока не деплоили. Если логи не идут вообще — проблема
с RPC, прогони `chain-probe`.

**Слишком много уведомлений.** Главная ручка — `mint.min_unique_minters`
в `config/config.yaml`. Подними с 10 до 25-30: узнаешь о проекте чуть позже,
зато только о тех, которые реально разбирают. Вторая ручка — поставить
`alerts.notify_deploys: false`, тогда пропадут сообщения о новых контрактах
(самый ранний, но и самый шумный сигнал: контракт может так и не начать минт).

**Пролезает какой-то конкретный контракт.** Скопируй его адрес из алерта
в `mint.ignore_contracts` — про него больше не сообщат.

**Слишком мало находок.** Опусти `min_unique_minters` до 5 и убедись, что
`notify_deploys: true`.

**Всплески не ловятся или ловятся постоянно.** Крути `chain.surge_threshold` —
число минтов в одном блоке, считающееся всплеском. В медленной сети 25 много,
в быстрой мало.

**Карточка проекта перестала обновляться.** Скорее всего слежение
остановилось — коллекция распродана, цифры не менялись двенадцать проверок
подряд, или прошло двое суток. Это нормально, не поломка. Посмотреть,
что происходит: `python -m wlparser top`.

**Подписчикам ничего не приходит.** Проверь `python -m wlparser subscribers` —
возможно, они отписались или заблокировали бота, тогда стоит статус «отписан».

**Ошибка про кодировку в консоли (Windows).** Не должна возникать, но если
вдруг — запусти `chcp 65001` перед командой.

**На Mac скрипт пишет `command not found` или `
`.** Файл скопировался с
виндовыми переводами строк. Лечится так:
`sed -i '' 's/
$//' *.command`

**Время в логах не совпадает с местным.** Часовой пояс контейнера задаётся
в `docker-compose.yml` (по умолчанию `Europe/Moscow`). Поменять разово —
`TZ=Asia/Almaty ./mac-start.command`, насовсем — правкой файла.

**Посмотреть логи контейнера.** `docker compose logs -f` в папке проекта.
Обновить бота после изменений в коде: `docker compose up -d --build`.

## Как это устроено

Источники независимы: каждый кладёт события в общую очередь и ничего не знает
об остальных. Дальше единый конвейер — дедупликация, оценка, обогащение
ссылками, уведомление. Падение одного источника не трогает другие.

```
OnchainSource ──┐
                ├──▶ Очередь ──▶ Дедуп ──▶ Оценка ──▶ Обогащение ──▶ Telegram
TwitterSource ──┘                   │                    ссылками
                                    ▼
                          SQLite (data/wlparser.sqlite)
```

Блокчейн даёт факты: контракт либо задеплоен, либо нет. Твиттер даёт раннее
предупреждение, но вперемешку со слухами и мусором. Ценность в связке: если
про контракт пишут в твиттере И он уже виден в сети — это сильный сигнал.
Именно на этом построен этап 4.

Подробности — в [дизайн-документе](docs/superpowers/specs/2026-09-08-wl-parser-design.md).
